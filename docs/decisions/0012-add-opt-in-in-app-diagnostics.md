# ADR-0012: 在应用内提供可显式开启的内存调试日志

- Status: Accepted
- Date: 2026-09-13

## Context

三个内置工具会将底层失败转换为可理解的界面提示；这些提示缺少原始错误和时间，用户难以准确描述并复制问题。当前需求是显式开启调试模式后，在应用内按大模块实时查看、筛选和复制错误，同时保持出错工具可操作，以便立即重现。

工具仍须独立编译，不得依赖宿主实现；股票看盘工作由可见内容拥有，打开诊断不能替换主内容并取消正在观察的刷新。

## Options considered

- 仅使用系统 Console：已有性能 signpost 可保留，但不满足应用内查看、按三个工具分类和复制原始失败的需求。
- 将日志作为第四个工具页面：可以复用主导航，却会切走当前工具并改变其生命周期。
- 通过现有 Runtime 接口上报，由 Host 缓冲、App 打开独立日志窗口：保留模块隔离及主工具挂载，但需要在窗口间管理工具与错误。
- 通过现有 Runtime 接口上报，由 Host 缓冲并在主工作区底部内嵌日志：保留模块隔离及主工具挂载，可以在同一窗口重现并查看错误。

## Decision

- 使用现有 Runtime 的 `ToolDiagnostics` sink 与 `DiagnosticEvent`；三个 registration factory 接受默认 no-op 的诊断参数。组合根绑定模块 ID 和展示名称，不新增共享 module 或动态注册机制。
- 工具在捕获错误、归一化为展示结果前上报。Error 记录保留原有描述、domain/code 和可取得的最深层 underlying error；原始校验消息也可直接记录。任务、网络及用户取消不计为错误。
- Host 拥有 `DebugLogStore` 和 `DebugLogView`。调试默认关闭；开启后才接收事件，并在主 actor 入队前移除用户/临时目录路径、URL 查询/凭据和授权等敏感字段。日志正文不新增用户内容或完整请求。
- 进程内仅保留按发生时间排序的最近 500 条，较早记录被淘汰；关闭采集保留已有记录，清空使尚未入队的旧事件失效。日志不写磁盘、偏好或数据库，不上传；退出即丢弃。
- App 仅将调试开关保存到 `onebox.debugMode`；`--debug-mode` 可直接开启本次运行。UI 测试不读取或写入用户的调试偏好。
- Host 在主窗口工作区底部以 SwiftUI `VSplitView` 内嵌日志，保留上方工具内容的稳定身份和操作区域；分隔线可调整日志高度。App 提供剪贴板 adapter 与 `⇧⌘L` 命令，不创建独立日志窗口。
- 侧栏与 `⇧⌘L` 切换日志展开状态；侧栏展开时选中当前工具，快捷键保留已有筛选。Runtime 的 `OpenToolDiagnosticsAction` 始终展开并筛选当前模块。关闭按钮只收起日志，不清空记录或关闭采集。日志不成为工具、不替换主内容，也不启动未选择工具。
- 界面按全部或三个工具筛选，支持错误、操作和时间文本搜索、单条和筛选结果复制。记录保留发生时间，复制格式含毫秒及时区。

## Consequences

- 用户可以在重现失败时直接复制有模块、时间和操作上下文的底层错误；三个工具保持对 Host 实现的独立性。
- 开启前或上一次进程的失败不可追溯；需要开启调试后重现。该功能只接收已接入边界的错误，不采集进程崩溃或系统全量日志。
- 原始错误的诊断价值依赖上报位置；新增失败路径必须在丢失底层错误前接入，并保持脱敏规则和全部消费者的验证。
- 展开日志会共享主窗口的纵向空间，需要在最小窗口、右侧检查器同时展开以及连续开关时验证工具仍可操作，且不会触发重新挂载或工作取消。

## 2026-09-13 呈现方式修订

最初的独立日志窗口已实现。用户随后明确要求日志内嵌，因此将日志呈现移入 Host 的主窗口工作区；App 持有展开状态并注入 Binding，同时继续拥有平台复制能力、快捷键和偏好。Runtime 诊断接口、模块隔离、采集与脱敏规则不变。
