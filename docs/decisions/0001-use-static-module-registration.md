# ADR-0001: 使用静态模块注册

- Status: Accepted
- Date: 2026-08-24

## Context

OneBox 的工具由同一作者开发、编译和发布。项目需要复用宿主和设计系统，同时用编译边界隔离工具实现；当前没有第三方分发或远程代码加载需求。

## Options considered

### 独立应用

隔离最强，但会重复宿主、工程和发布流程。

### 动态插件

支持独立安装，但会引入签名、来源信任、兼容、升级和供应链安全问题。

### 静态注册的模块化单体

工具随应用构建，通过类型安全 registration 进入组合根，满足当前复用和隔离需求。

## Decision

- 内置工具使用静态注册的模块化单体；`AppComposition` 是唯一组装 `ToolCatalog` 的组合根。
- 无依赖工具可以公开静态 `ToolRegistration`。需要依赖时，工具公开窄 factory，由组合根注入平台能力或配置。
- `ToolRegistration` 只包含 ID、展示名称和内容构造方式，不包含后台激活策略。
- 内容在被选择时构造；应用启动时默认打开第一个 registration。未打开工具不执行业务 I/O。
- 不使用 JSON manifest、磁盘扫描、动态插件或远程代码加载。

## Consequences

- 注册信息和实现接受编译器检查，没有第二份配置源。
- 更新任意工具都需要重新构建和发布 OneBox。
- 所有工具仍在同一进程中，可能通过崩溃或主线程阻塞影响整个应用。
- 首个启动后台任务需求出现时，必须同时定义宿主调度、生命周期测试和新的 ADR。
