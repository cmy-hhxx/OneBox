# 工程规范

本规范只约束软件开发、代码审查与技术操作，不能削弱明确的安全、隐私、合规、数据保护或外部兼容承诺。

## 目标与范围

- 开始前写清目标、支持范围和可验证的成功标准。
- 做最小但完整、可维护的改动，不顺手扩展需求。
- 信息不足但可安全推断时采用最小合理假设；只有选择会实质改变结果、架构或风险时才提问。
- 真实输入、公开接口或支持环境可触发的问题必须处理；当前范围不可达的理论状态不增加实现。

## 简单性与兼容

- 选择满足当前需求的最简单实现，不做预防性抽象或多余配置层。
- 不添加无现实需求的校验和、feature flag、迁移框架、兼容包装、回退链或重复守卫。
- 接口或内部数据格式变化时，在同一个变更中更新所有当前调用者并删除旧实现。
- 不保留 deprecated 入口、shim、双写、migration 或 fallback。
- 上述规则不授权静默删除用户数据或违反已经明确的外部承诺。

## 增量交付

- 先在 README 的“当前业务竖切”中写清选定工具的用户结果、真实输入、排除范围、失败状态和完成检查，再实现打开并显示真实结果的最小端到端竖切；切换竖切时直接更新该节，不并列维护过期计划。
- 每一步保持主路径可运行，不先横向铺满所有层。
- 新结构只在当前竖切需要时出现，不为未完成的复杂度拆掉能运行的路径。
- 用于消除关键不确定性的 spike 必须明确可丢弃，不能未经决策成为生产基础。

## 模块与代码

- 模块使用小接口隐藏深实现；不暴露内部 store、client、view model 或线程模型。
- 第二个真实消费者出现前不抽取共享模块；没有真实变化或测试替代需求时不创建接缝。
- 禁止全局可变业务状态。异步任务必须有 owner、取消点和超时，不在 UI 主线程执行阻塞 I/O。
- App、Host 和 Design System target 默认隔离到 `MainActor`；Runtime 与工具 target 默认 `nonisolated`，其中 UI 状态和视图入口显式使用 `@MainActor`。
- 使用类型化错误，不用字符串匹配决定错误类型；有意降级必须返回可观察结果。
- 代码标识符和提交消息使用英文。注释解释约束和原因，不复述代码。
- 使用事实标准格式器和静态检查；生成文件必须有可追溯的生成源和命令。

## 依赖与调研

- 实现前先检查现有依赖、锁文件、源码用法和官方文档，不得未经检查就假设能力缺失。
- 现有依赖不能满足时，优先选择成熟、持续维护且许可证合适的库；没有明确理由，不自行重写成熟能力。
- 新依赖必须对应当前需求，并说明已有依赖为何不足、维护状态、许可证和删除成本。
- 非平凡架构或交互先看成熟产品和一手资料；简单机械改动不做形式化调研。
- 架构决定面向已知产品范围长期维护，不接受计划整体替换的临时生产方案。

## 测试与验证

- 模块接口也是主要测试表面；测试用户可观察行为和生命周期不变量，不穿透接口断言实现细节。
- bug 修复先写稳定复现测试；无法自动化时记录复现步骤、期望结果和人工验证证据。
- 本地可替代依赖使用真实 stand-in；第三方或平台能力使用窄测试 adapter。
- 局部变化运行相关测试和静态检查；共享接口覆盖全部当前消费者；权限或平台接缝覆盖相应回归路径。
- 数据格式变化只验证当前格式并确认旧代码删除，不测试 migration 或 fallback。
- 不重复运行未受影响且已经通过的检查；未验证事项必须明确说明。
- UI 变更必须先逐项核对[设计规范](design.md)中的“不可回退的设计决定”，再在默认窗口和最小支持窗口下验证锁定的浅色配色、字体、图标、共同边线和数字列对齐；深色当前只检查占位结构。模板、参考产品或生成代码不能作为突破这些决定的理由。
- UI 验收过程和比较结论记录在 [design-qa.md](design-qa.md)。界面截图只作为当次本地检查的临时工作产物，不提交仓库，也不使用截图文件做版本管理；验收结束后必须清理。验收记录不得引用用户目录或系统临时目录，也不替代 `docs/design.md` 中的设计契约。

### 本地产物目录

| 产物 | 目录 | 生成方式 |
| --- | --- | --- |
| Xcode 工程 | `OneBox.xcodeproj` | `./scripts/bootstrap.sh` |
| DerivedData | `.build/DerivedData` | `./scripts/test.sh` |
| Release 基准 DerivedData | `.build/DerivedData-Release` | `./scripts/benchmark-ascii.sh` |
| 测试结果 | `.build/TestResults` | `./scripts/test.sh` |
| 构建与测试日志 | `.build/Logs` | `./scripts/test.sh` |

这些目录以及本地打包使用的 `dist/` 都是可再生成产物，必须保持在 `.gitignore` 中。测试源码按被测接口放入 `Tests/<Module>`，并在 `project.yml` 中对应独立 test target；不得用一个可导入整个应用的测试 target 穿透所有模块实现。

提交前运行 `./scripts/check.sh`；它使用仓库根目录的 `.swift-format` 做严格格式检查，再生成工程并执行全部测试。

## 变更记录

架构、权限、存储布局或运行位置变化必须写 ADR。ADR 面向长期决定，旧决定被替代时保留历史但不并行维护两套实现。

提交使用：

```text
<type>(<scope>): <imperative summary>
```

常用类型为 `feat`、`fix`、`docs`、`refactor`、`test`、`build`、`ci`、`chore` 和 `perf`。一次提交只表达一个可回滚意图。
